# صلاحيات جرد Cloudflare

ظهر في `wrangler whoami` أن الاعتماد الحالي OAuth بنطاقات قراءة المستخدم والحساب وكتابة Pages و`offline_access`. يستخدم مشروع Pages الحالي `safaqat` هذا الاعتماد للنشر. أعاد مسارا القراءة `/accounts/{account_id}/d1/database` و`/accounts/{account_id}/r2/buckets` خطأ المصادقة `10000`. صلاحيات Pages لا تمنح صلاحية جرد قواعد البيانات أو الحاويات أو قراءة ارتباطات Workers.

| المطلوب | الصلاحية القرائية | الموارد المتأثرة |
|---|---|---|
| قائمة قواعد D1 | `D1 Read` | قواعد حساب صفقات. اسم القاعدة المقصودة ومعرّفها غير مثبتين. |
| قائمة حاويات R2 | `Workers R2 Storage Read` | حاويات حساب صفقات. اسم الحاوية المقصودة وخصوصيتها غير مثبتين. |
| قائمة Workers ومراجعة الارتباطات | `Workers Metadata Read-Only` على مستوى المنتج | الارتباطان `DB` و`BUCKET` في شفرة الكتالوج المحلية قرائن فقط. |

## إجراء المالك

1. افتح حساب صفقات في Cloudflare. للجرد اليدوي، يكفي تقديم أسماء ومعرّفات قواعد D1 والحاويات وأسماء Workers وارتباطاتها من اللوحة، مع حالة الوصول العام للحاويات ومعلومات النسخ الاحتياطية إن كانت ظاهرة. احجب قيم الأسرار وأي سجلات عملاء.
2. للجرد عبر API، افتح **Manage Account → Account API Tokens → Create Token → Create Custom Token**. اختر حساب صفقات وحده وحدد تاريخ انتهاء قصيرًا. أضف `D1 Read` و`Workers R2 Storage Read` وامنح `Workers Metadata Read-Only` لبيانات Workers. إذا كانت واجهة الصلاحيات التقليدية هي المتاحة، يتيح `Workers Scripts Read` قراءة قائمة Workers. يظل خيار تقديم البيانات الوصفية من اللوحة أضيق من منح قراءة المحتوى عند عدم الحاجة إليها.
3. أودع الرمز عبر مخزن الأسرار المعتمد للجلسة باسم `CLOUDFLARE_API_TOKEN`. أبلغ المنفذ بعد الإيداع دون إرسال قيمة الرمز في المحادثة أو في GitHub. أبق اعتماد Pages الحالي منفصلًا. هذه المرحلة تحتاج قراءة فقط.

المراجع الرسمية [إنشاء الرموز](https://developers.cloudflare.com/fundamentals/api/get-started/create-token/) · [قائمة قواعد D1](https://developers.cloudflare.com/api/resources/d1/subresources/database/methods/list/) · [صلاحيات R2](https://developers.cloudflare.com/r2/api/tokens/) · [صلاحيات Workers](https://developers.cloudflare.com/workers/authorization/workers/).

## إعادة الفحص في 24 نوفمبر 2026

أكد المالك تفعيل R2. فُحص وجود `CLOUDFLARE_API_TOKEN` داخل بيئة التنفيذ العادية والمصرح لها بالشبكة دون طباعة القيمة. المتغير غير متاح في البيئتين. انتهت صلاحية اعتماد Wrangler المخزن، وانتهت محاولة قراءة سجل Pages باستخدامه بعد 30 ثانية. لذلك لم تُنفّذ طلبات مصادقة جديدة إلى D1 أو R2 أو Workers، ولا يمكن استنتاج أن صلاحيات الرمز الجديد مرفوضة أو أن قائمة الموارد فارغة.

| المورد | ما ثبت | ما يلزم إكماله |
|---|---|---|
| Pages | عنوان الإنتاج أعاد HTTP 200. آخر نشر موثق في سجل المشروع هو `d3f1b753-5e78-4fb8-868b-80a2369ff7cb`. | التحقق من سجل النشر الحالي والرجوع إلى النسخة السابقة. |
| D1 | الجرد السابق أعاد الرمز `10000` باعتماد آخر. | أسماء القواعد وبيئاتها وارتباطاتها، وعزل قاعدة المشتركين عن الكتالوج، والتحقق من الاسترداد. |
| R2 | المالك أكد تفعيل الخدمة. | أسماء الحاويات وخصوصيتها وارتباطاتها وسياسات الاسترداد. |
| Workers | رمز القراءة الجديد غير متاح. | أسماء العاملين والبيئات والارتباطات دون قراءة قيم الأسرار. |

تبقى صلاحيات الجرد مستقلة عن النشر. بعد إثبات الموارد القائمة، يكفي دور `Editor` للعامل المقصود لنشره مع ارتباطاته. يحتاج تنفيذ ترحيلات D1 مباشرة إلى اعتماد منفصل بصلاحية `D1 Write` للحساب المعني، ويبدأ التنفيذ بقاعدة الاختبار المحددة. إذا تعذّر تضييق الرمز إلى قاعدة واحدة، ينفذ المالك الترحيل بعد مراجعة القاعدة والنسخة الاحتياطية بدل تداول رمز أوسع. يُفضّل استخدام ارتباط R2 لحاوية الوثائق الخاصة؛ وإذا لزم وصول S3 مباشر فيقتصر على الحاوية المعنية. صلاحية `Pages Write` مطلوبة فقط لاعتماد النشر المنفصل عند الحاجة. تحتاج صلاحية `Workers Routes Write` إلى مبرر منفصل عند تغيير المسارات أو النطاقات. لا تتطلب الدفعة الحالية أي تعديل للسحابة.
