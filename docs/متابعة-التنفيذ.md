## بناء إصدار الواجهة

من مجلد `app` بعد تثبيت الاعتماديات المقفلة، تُشغّل الأوامر بالتتابع.

```bash
./node_modules/.bin/eslint src next.config.ts
./node_modules/.bin/tsc --noEmit
SAFAQAT_PAGES_EXPORT=1 RAYON_NUM_THREADS=1 UV_THREADPOOL_SIZE=2 NEXT_TELEMETRY_DISABLED=1 NODE_OPTIONS=--max-old-space-size=768 npm run build -- --webpack
```

ينتج التصدير الثابت في `app/out`. يعمل إعداد التصدير عند تمرير `SAFAQAT_PAGES_EXPORT=1`. يُرفع التصدير إلى مشروع Pages `safaqat` على فرع النشر `production` مع إسناده إلى الالتزام المرفوع في GitHub. معرّف نشر الإصدار السابق `fd8640e5-bb2e-43e5-95d2-78409ed324e0`، ومرجع الإصدار الذي سبقه `82915eca-03bf-4f43-8d56-253b271c8473`.

- أُضيف تحقق التسجيل على الخادم كمنطق مستقل قابل للاختبار، مع عمر 18 عامًا وقبول السياسات حسب الفئة والتحقق من القوائم المورّدة والتعامل مع إجبارية البريد. يحتاج ربطه بواجهة وواجهة برمجية وقوائم رسمية. يقدَّم عنوان البريد المطلوب لتجار التجزئة ووثائق التحقق وفق القسم 12 الأحدث، الذي يحل تعارض وثائق هوية التاجر مع المواصفة القديمة.

- مسار الاستئناف المستقل هو إضافة مزود تحقق قابل للاستبدال ومخزن تحديات بإبطال ذري ومنع إعادة الاستخدام، ثم إصدار الجلسة واستردادها ذريًا واختبار التزامن. تبقى واجهات التسجيل والوثائق والعمليات التجارية معطلة. يوضح [دليل الصلاحيات](صلاحيات-الجرد-السحابي.md) الإجراء المطلوب لفتح الجرد وإثبات الموارد الموجودة.

### قيد الجلسة وتسجيل الخروج

يستخدم `backend/sessions.mjs` كتابة SQL واحدة لحجز جلسة جهاز واحد للحساب النشط. تظل الجلسة السارية صالحة عند رفض طلب ثانٍ، ويخزن الخادم بصمة رمز عشوائي بدل الرمز. تشمل اختبارات SQLite طلبَي دخول ورفض الجهاز الثاني وانتهاء الصلاحية والخروج وإبطال الجلسة عند التعليق. يمكن إعادة تشغيل الاختبارات بأمر `node --test --test-concurrency=1 backend/tests/*.test.mjs`. الواجهة الخلفية غير منشورة. يحتاج الاستكمال إلى ربط التحديات والمزود والاسترداد وسجل التدقيق وملفات الارتباط الآمنة، ثم تحقق D1 معزول ومعاينة الاسترداد قبل التفعيل. لا يستدعي المتصفح إصدار الجلسة مباشرة.

### تحديات التحقق دون كلمة مرور

خطوة الربط التالية هي اعتماد حد المحاولات والصلاحية، ودمج الاستهلاك مع انتقال التحقق وإصدار الجلسة وسجل التدقيق بمعاملة واحدة، ثم تنفيذ الاسترداد وقواعد تغيير جهات الاتصال. يحتاج الجرد والنشر الخلفي إلى الموارد القائمة المعروفة واختبار D1 معزول. تظل WhatsApp مؤجلة.

## معاينات التسجيل الأربع

ربطت بطاقات المورد والتاجر والمستهلك والشحن والتوصيل بمعاينات تسجيل عربية وإنجليزية داخل النافذة الحالية. تعرض الحقول المشتركة والحقول الخاصة بالنشاط أو المركبة، وتوضح الوثائق والسياسات وآلية التفعيل لكل فئة. اختبار الحقول يعمل داخل المتصفح ببيانات اصطناعية فقط. نموذج HTML يعمل بطريقة `dialog` دون مسار إرسال أو أسماء حقول أو رفع ملفات أو حفظ محلي. أُبقي اختيار التغطية وقبول السياسات معطلين إلى حين ربط القوائم والنسخ المعتمدة، ولم يُفعّل أي تحقق فعلي.

نجحت ESLint وTypeScript وعملية التصدير بعامل واحد. اجتاز Chrome محليًا فتح المعاينات الأربع، والتباين بين الفئات، والتحقق من عينة مستهلك، والتحويل للإنجليزية، وشاشة البدء والمشاركة وإرشادات التثبيت وService Worker. تأكد استمرار توقف خدمات الجمع السبع. لم يصل اعتماد قرائي جديد عند الفحص وأظهر Wrangler نطاقات OAuth السابقة، لذلك بقي جرد D1 وR2 وWorkers معلقًا دون إعادة طلبات القراءة المرفوضة.
